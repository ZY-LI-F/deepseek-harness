# @deepseek-ai/dsh-client-ui-task-garden

[English](README.md) | 中文

Task Garden 仍通过 `conversation.viewport.overlay` 获取会话状态，但可穿透点击的画面使用整个页面的固定坐标系。因此花藤边会围住侧栏、对话区和详情栏，而不再只围住中间正文。它没有卡片背景、模糊、边框或阴影，并通过 `pointer-events: none` 保证底层控件都能正常操作。`ResizeObserver` 测量整页实时范围，而不是强加固定尺寸；随后，纯圆角边框几何会根据当前宽高推导圆角半径、花藤密度、吸附点、底部花园容量和浇水起点。经审核的 Z-Image 蓝发鲸鱼女孩固定在页面左下角，与自适应花藤几何彼此独立。

会话运行时，每个新观察到的工具调用或权威步骤增量都会从左下浇水起点发射一朵由本机 Z-Image 生成的独立花头。一小段直藤把女孩与页面左边缘的最近点连接起来，花朵会漂向当前生长前沿，并产生轻微的磁吸过冲。落位后，花头会直接以中心贴合的方式稳定吸附在藤蔓上，不带茎叶，也不留悬空间隙；若浏览器遗漏 CSS 动画结束事件，则由幂等的 2.85 秒兜底逻辑执行同样的落位。事件花朵填满一圈的所有自适应边缘 slot 后，会继续装点下一圈向内的花藤。画面同时保留三圈花朵；第 4 圈开始时会复用第 1 层视觉轨道并移除第 1 圈，而不是不断替换右下角的最后一朵。这些事件花朵负责即时反馈，而四周花藤刻意保持缓慢：它会把持久化的 `llmMs + toolMs` 与每秒更新一次的实时计时对齐，并且只在任务运行时前进。任务停止或完成后，画面会冻结在当时的准确状态。

每经过 10 分钟实际任务时间，就开始一圈新的自适应花藤；每圈用 10 分钟从左侧接点向上出发，顺时针绕完整个页面并回到起点闭合。每圈从萌发开始只存在 30 分钟，最后 1 分钟柔和淡出。因此无论任务多长，页面最多同时保留 3 圈。相邻圈会依次轮换 4 套不同的 Z-Image 花藤样式，使用稳定的会话种子镜像，并且每层按当前自适应花朵尺寸的 1.22 倍向内错开。事件花朵也使用相同的自适应间距，层间距离略大于花朵的显示直径，因此不需要固定页面尺寸也能保持三圈彼此分明。每个可见圈最多点缀 1 朵 V21 蓝色大花头，任务事件则会从 4 种蓝花和 4 种粉花中按会话稳定选择；这些素材全是透明背景的纯花头，不含茎叶。四角共用一组花簇和两只稳定选择的蝴蝶，不会随圈数成倍堆积。顶部花藤向内垂下，侧边随边框转向，紧凑的底边花藤保持在狭窄边缘带内；由步骤驱动的 12 段矮花园仍保留。运行中若缺少投影，阶段生长会回退到已加载的轮次索引，而实时圈层计时会从本次运行开始。

照料者使用经审核的完整人物 Z-Image 逐帧图和事件驱动的动作状态机。唯一的 V22 身份母版就是指定的浇水立绘：宽圆脸、两只蓝青渐变大眼、上睫毛、小猫嘴、刘海、服装和身体比例在所有任务动作中保持一致。打包阶段会把每张 V22 图片中的透明主体统一为 450 源像素高，浏览器中的自适应角色画布再限制为最高 80 CSS 像素，因此切换动作不会再忽大忽小。任务运行时会循环播放 6 帧的四肢联动浇水步态，女孩、水壶落水和脚下着水点会一起在小草地上移动。水流层现在嵌套在移动的女孩节点内，并为 6 张动作帧分别设置壶嘴锚点，因此女孩走动和水壶逐帧变化都会同步带动水滴。每隔 5.5–10 秒以及花朵落位时，会按会话稳定地从赏花、欢呼、跳舞、挥手四套 4 帧动作中选择一套，结束后继续浇水。任务完成时仍依次鞠躬、飞吻并举杯。飞吻播放 8 张统一比例和脚底基线的完整人物逐帧图，三颗独立爱心会在肘关节主导的释放动作后沿斜向飞出；浏览器不会旋转或重接手和胳膊。配套 Godot 4.7.1 源场景预览人工设定的停留时长与特效；Godot 只用于创作与预览，不成为浏览器依赖。

该模块是只读的。它不会追加事件、存储重复的业务状态，也不会检查消息内容。照料动作、顺序生长和可选的 `garden-grow` 声音提示，只是对既有会话事实的展示；除非用户通过 Pocket Buddy 开启声音，否则音频保持静音。`ui-agent-theater` 源码包仍可供复用，但 Web 组合包不挂载独立的办公长条场景，其工作坊媒体也不是运行依赖。

## 模型体验

### 仅浏览器端的只读模型

#### 模型看到的内容

无。Task Garden 只在宿主折叠完成后读取现有的 `sessionStats` 和 `running` Client 投影值；它不会注册系统提示词、注入上下文、工具 schema 或工具结果。

#### Token 影响

无。覆盖层不会增加、删除或重排任何模型请求 token。

#### KV Cache 影响

无。该包从不参与提示词组装，因此不会改变可复用前缀或追加式请求后缀。

## 已知限制和后续工作

- 生长进度属于单个会话，而不是跨会话累计的每日花园。
- 缺少 `sessionStats` 的组合会看到窗口范围内的进度，因此加载更早的历史记录可能推进回退植物。
- 底部花园仍以十二段矮花藤为上限；每圈边框保持 12–36 个 slot，计时花藤和事件花朵都只保留滚动的 3 圈，因此长任务最多保留 108 朵已落位的事件花朵，不会添加无界 DOM 节点。
