# Agent Note: 可观测任务路径与知情位置地图

Status: implemented

[English](2026-08-24-task-knowledge-map.md) | 中文

## 问题

DSH 已经提供线性执行轨迹、嵌套工具展示、工作流折叠区和 subagent 导航，但缺少一个统一的 Session 界面来回答两个相关的运维问题：当前执行到哪个分支，以及所选位置存在哪些可观测信息来源。把这些来源当成模型内部知识同样会形成误导且不安全的约定，因为隐藏推理和子级上下文都不是权威 Client 数据。

## 决策

`@deepseek-ai/dsh-client-ui-task-knowledge-map` 注册一个仅浏览器端、只读的 `conversation.view` 标签页。纯函数投影 `buildTaskKnowledgeMap(...)` 将 Session Chat 时间线、组装后的工作流与工具行、运行中调用、对话节点、队列和 Session 目录组合为有界执行图与信息账本。React 视图会渲染所有活跃分支、一个确定性的当前叶节点、按位置限定的信息、搜索、缩放和明确的截断提示。

该包复用现有快照约定，不新增 Host 服务、事件类型、持久投影或 Remote 方法。重新加载和回放都会再次推导该视图，插件 dispose（资源释放）时会移除注册的所有浏览器资源。

## 可观测知情状态约定

该视图中的“知情”是父 Session 中可观测的信息：用户要求与 steering（中途引导）要求、注入上下文与召回来源、工具结果、可见的 assistant 文本、压缩摘要、异常与重试、排队输入和委派元数据。隐藏推理块不会被展示或推断。最新压缩之前的信息仍作为历史保留，并标记为“已压缩”。选择带有已完成序列号的节点时，只展示不晚于该序列号的项目；实时尾部还可以展示排队上下文。

subagent 节点刻意只展示父级可见的任务和状态。插件不会合并子级 transcript（文本记录），也不会声称能够看到子级内部上下文。UI 会明确标注这条边界，而不是把委派元数据呈现成子级知识。

执行图最多保留 56 个工具节点，信息账本最多保留 160 条。它保留最早的用户要求和最近信息，并报告省略数量，因此长 Session 不会产生无界的浏览器工作量。

## 考虑过的替代方案

**扩展 Trajectory。**Trajectory 负责按时间顺序检查事件。把拓扑、分支选择和累计信息语义加入其中，会混合两种交互模型，也会让现有线性视图更难扫描。

**依赖外部 agent canvas。**通用画布可以展示 agent 拓扑，但不拥有 DSH 的 Turn、Step、工具、队列和压缩约定。让这个核心视图依赖第三方 schema，会削弱回放保真度和默认安装体验。

**推断隐藏推理或确定的模型信念状态。**可观测提示词和输出无法证明模型内部保留或相信了什么。这类推断会夸大确定性，也与产品对私有推理的边界冲突。

**持久化新的任务地图事件流。**所需事实已经存在于权威 Session 快照中。复制它们会增加排序、迁移和恢复义务，却不能改善当前只读体验。

## 验证

纯投影测试覆盖活跃和已完成的 Turn/Step 路径、工作流、subagent、嵌套与运行中工具、压缩、隐藏推理排除、异常、畸形扩展行、确定性布局和边界。浏览器测试覆盖位置选择、委派范围、搜索、缩放、跟随当前、Session 响应式变化、本地化注册、slot 清理、空 Host 行为和不变量归属。包级类型检查和构建固定公开浏览器产物。

## 影响

DSH 在不改变模型请求或持久 Session 语义的情况下获得原生运维地图。该视图诚实标注可观测边界，并在长任务中保持有界；代价是不展示尚未加载的历史、子级内部路径、推断信念、任意执行图编辑或持久化手工布局。
