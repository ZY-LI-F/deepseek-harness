# Agent Note: Task Garden 事件花朵使用滚动圈层

Status: implemented

[English](2026-08-17-task-garden-rolling-blossom-rings.md) | 中文

## Problem

Task Garden 曾把每朵落位的事件花朵分配到一个有上限的边缘索引。第 1 圈到达右下角的最后一个 slot 后，后续每次工具调用或步骤都会复用这个点。固定的尾部数量上限虽然限制了内存，却没有提供下一圈可见花朵，还可能截掉一段与圈层无关的局部装饰。

## Decision

每朵事件花朵都携带一个绝对序号。自适应 slot 数量把该序号划分为从零开始的圈号和圈内 slot。圈号在 3 个视觉层之间循环；每层按当前自适应花朵尺寸的 1.22 倍向内移动，间距略大于花朵的显示直径。

状态只保留当前圈及其前两圈。第 4 圈开始时会复用第 1 层，同时移除第 1 圈。后续圈层继续使用相同的滚动规则，因此复用视觉层时不会在同一坐标留下两代花朵。飞行花朵和已落位花朵通过同一序号映射推导目标；页面尺寸变化后，落点和保留范围都会按新的自适应 slot 数量重新计算。

## Alternatives considered

**继续把索引限制在最后一个 slot。** 否决，因为持续进度看起来像停住，并且会反复遮盖右下角同一朵花。

**保留所有已完成圈层。** 否决，因为长任务会积累无界的图片节点，并逐渐遮挡页面。

**只保留固定数量的最新花朵。** 否决，因为数量上限可能从一圈中间截断，也不能说明哪个视觉层可以安全复用。

## Consequences

事件花朵现在依次填满第 1、2、3 圈。第 4 圈开始时会先移除第 1 圈再复用其坐标，第 2、3 圈仍然可见。在最大的自适应密度下，覆盖层最多保留 108 朵已落位事件花朵。聚焦组件测试会驱动四个完整圈层，并验证层间分离、第 1 圈淘汰以及最终只保留 3 圈。
