# Agent Note: 完整角色逐帧猫咪与自由漫游

Status: implemented

[English](2026-08-15-source-pixel-cat-free-roaming.md) | 中文

## Problem

程序化 3D 外壳无法保持已确认的桃桃猫形象；从一张扁平图切出四肢制作 2D 骨骼，又会因为缺少被遮挡的身体像素而产生断腿、重复脚掌和接缝。侧面角色沿任意斜线移动时也会与实际行进方向不一致，看起来像漂浮。

## Decision

桃桃猫使用完整角色逐帧动画。侧向、朝向用户、背向用户分别有 8 张透明完整身体帧；右向由完整侧向帧镜像得到。梳洗、伸懒腰、趴下、睡觉、醒来、观察、点击回应、扑球和转身也都使用经过确认的完整角色序列。当前渲染器不存在运行时关节拼接。

自主移动在视口安全边界内采样连续像素坐标，不使用路径点图。角色以每秒 64 像素线性前进；每移动 72 像素完成一次 8 帧循环。移动向量选择最接近的左、右、朝向用户或背向用户素材，因此侧面猫不会被旋转到斜向路线。爪印使用同一累计位移生成。

方向变化使用完整角色过渡，不会变形或拆分身体。带权动作编排器会组合姿态兼容的完整角色序列，避免近期动作重复，在相邻梳洗动作之间复用坐姿过渡，并把单段自主表演限制在 18 秒内。

任务暂停或完成后，自由活动会让位于一条走向鲸鱼女孩的直接路线。猫咪在她身边趴下，并默认保持持续睡眠。互动会先唤醒猫咪，在原地播放后重新入睡；任务恢复时则先醒来，再重新开始随机活动。

## Alternatives considered

**继续打磨 2D 切片骨骼。** 否决，因为被前腿和身体遮挡的像素并不存在，调蒙版不能重建可靠解剖结构。

**恢复三张整帧循环。** 否决，因为三张接触帧不足以表达脚掌抬起、摆动和落地，也无法覆盖前后方向。

**使用固定路径图。** 否决，因为有限连接会暴露重复规律。连续随机终点和逐帧线性积分仍是唯一移动真源。

**继续使用程序化 3D 猫咪。** 否决，因为现有网格和材质无法保持已确认的插画角色身份；3D 渲染还会增加体积与调参成本，却没有改善普通用户最关注的页面宠物动作。

## Consequences

桃桃猫在行走和表情动作中保持同一角色身份，不会出现断肢或多余脚掌。四个绘制方向覆盖主要屏幕路线，步态帧与位移同步；停靠后的睡眠状态为暂停或完成提供稳定的视觉终点。新增表情仍需补充经过确认的完整角色序列，运行时不会再用切片或程序化骨骼冒充。
